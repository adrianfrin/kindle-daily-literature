这套方法先找到一个值得反复思考的人的问题，再寻找最适合承载它的人物、作品和历史场景。选书、介绍思想家、解释概念，都服务于这个问题。读者先进入一个人的故事，逐渐感觉到其中的矛盾，最后发现这个矛盾也发生在自己的生活里。

本文根据原对话中的完整方法论整理，供本地 Agent 复刻使用。评分阈值、段落长度和篇幅是经验尺度，不是质量保证；目录、角色和配置是建议架构，不代表已经存在一套经过运行验证的程序。文中标为“实现建议”的内容用于补齐本地执行细节。

## 一、整体流程：选题 → 研究 → 写作 → 编辑发布

长期栏目质量主要取决于选题、研究和最后的编辑。模型第一次想到的题目未必最好，第一稿也不应直接发布。

流程从长期偏好与近期文章历史开始。先产生多个候选问题，检查故事入口、思想深度和重复程度；选定后研究原作、人物与历史背景，再写正文。编辑时核对事实、收紧论证、合并短段、删除空泛判断。只有通过编辑的文章才进入保存或发布环节。

这里的复刻目标是稳定的阅读体验：有故事，有复杂性，有思想递进，也能回到普通人的生活。它不依赖堆积名人、调高模型温度，或套用某一种表面文风。

## 二、选题方法与 TopicSelector 候选评分

### 从兴趣坐标系生成问题

长期兴趣可以围绕五条主轴展开：

| 主轴 | 典型关注 |
| --- | --- |
| 存在主义与个人选择 | 自由、责任、死亡、可能性、后悔、怎样生活 |
| 现代性与规训 | 福柯、工作、自我管理、绩效、社会角色、正常化 |
| 二十世纪历史与记忆 | 苏联、东欧、战争、极权、历史责任、普通人 |
| 文学中的普通生活 | 契诃夫、石黑一雄、卡夫卡、张怡微、家庭、爱情、失败者 |
| 中国文学里的个人命运 | 陶渊明、古典诗词、鲁迅，以及具体的人怎样活 |

每期先生成问题，再决定用谁、用哪部作品来展开。**题目必须首先是一个人的问题，而不是一个知识主题。**

| 知识主题或人物 | 转换成可写的问题 |
| --- | --- |
| 福柯与规训理论 | 为什么没人监督，我们还是越来越不敢偷懒？ |
| 石黑一雄《长日将尽》 | 一个人把一生献给“正确的工作”，为什么最后只剩下后悔？ |
| 陶渊明 | 陶渊明辞官以后，真的获得自由了吗？ |
| 普里莫·莱维 | 当一个人没有选择，我们还有资格审判他吗？ |

标题里的问题应贯穿正文。不能只用问题吸引读者，正文却退回作者生平或作品梗概。

### 每次提出六个候选，再评分

TopicSelector 每次先读取最近 10～20 篇文章，再提出六个候选，不直接写第一篇。每个候选都要说明核心问题、主作品或人物、开场场景、辅助思想资源和通往今天生活的联系。

原方法使用六个维度，每项 0～5 分，总分最高 30 分：

| 维度 | 程序字段 | 判断依据 |
| --- | --- | --- |
| Narrative Hook：叙事入口 | `narrative` | 是否有具体的人、事件或场景，可以作为开头并继续展开？ |
| Human Question：人的问题 | `human_question` | 是否对应真实的人生困惑，而非纯粹的知识兴趣？ |
| Conceptual Depth：思想深度 | `depth` | 能否自然进入哲学或历史概念，使困境更清楚？ |
| Cross-link Potential：关联潜力 | `cross_link` | 能否连接另一位思想家或作品，让问题发生变化？ |
| Present Relevance：当下关联 | `present_relevance` | 能否自然落到今天的生活，避免硬蹭热点？ |
| Novelty：新颖程度 | `novelty` | 与近期文章相比，问题与论证结构是否有变化？ |

原方法的经验阈值是：总分低于 20 分不写；20～24 分作为备选；25 分及以上适合发展成完整文章。前两个维度最重要。一个题目即使概念很深，找不到具体故事入口，也不应优先写。

**实现建议：**统一分值口径：0 分表示没有支撑，1～2 分表示薄弱或牵强，3 分表示可用但仍需补材料，4 分表示清楚且有展开空间，5 分表示非常适合本期。每项附一句理由，避免只给数字。先检查是否有可核查的场景、是否近期重复，再比较总分；同分时优先比较叙事入口和人的问题。高分候选仍须经过 Researcher 核实，研究失败时退回备选。

### 轮换主题，保留一根细线

不能连续五期都讲存在主义，也不能换了作者却一直回答同一个“自由”问题。可以参考这样的轮换：

```text
个人存在 → 历史／制度 → 文学中的普通人 → 工作／现代性
→ 中国古典 → 东欧／苏联 → 再回个人存在
```

轮换不是机械排班。**下一篇最好和上一篇有一根细线相连，但不要重复回答。**例如，“为什么现代人要证明自己”可以接到“为什么人害怕闲下来”，再接到“如果没有工作，我还是谁”，最后进入《长日将尽》中职业吞掉人生的问题。另一条路线可以从自由，走向自由之后的失重、逃避自由，再走向《大审判官》中由别人替你决定幸福的诱惑。

栏目应像一条不断生长的思想路线。检查新颖程度时，要看主问题和论证结构，不能只检查作者姓名是否重复。

## 三、研究方法：先研究故事，再研究概念

先找到一个能够讲三五分钟的具体场景，再问它适合进入哪个思想问题。若研究一开始就按“福柯认为、萨特认为、阿伦特认为”收集材料，正文容易变成知识点堆砌。

以《长日将尽》为例，先确认需要使用的小说细节：1956 年的旅行、史蒂文斯的身份、达林顿庄园、父亲去世那一晚、犹太女仆事件、肯顿小姐离开，以及最后的海边长椅。这些是研究清单，写作前必须回到原作核实。然后才建立解释路径：

```text
职业角色 → 责任外包 → 萨特的自欺 → 现代组织伦理
→ 今天的人如何通过职业定义自己
```

理论要从故事里的矛盾长出来。不能先决定使用某个概念，再把人物压成概念的例子。

材料按三层处理。第一层是原作：小说、演讲、书信、哲学原文，它们是文章的支点。第二层是可靠背景资料，例如 Nobel Prize、Stanford Encyclopedia of Philosophy、Britannica、出版社、大学、博物馆或档案馆；Project Gutenberg、Wikisource 等可用于寻找原文，但仍需确认版本和译者。第三层才是论文、文学评论和学者访谈等二手解释。不能读了十篇别人怎样评价卡夫卡，却没认真看卡夫卡写了什么。

事实与解释必须分开。日期、人物身份、作品发表年份、历史事件、真实经历、直接引语，以及思想家是否确实提出某个概念，都要核查。直接引语应短，标明作品来源；不同译本的措辞不能混用。作者自己的理解可以写成“从这个角度看”“我更愿意把它理解为”“它让我想到”，不能伪装成史实或原作者的明确主张。

**实现建议：**Researcher 交付研究包，包含可用场景、关键事实及来源、短引文及版本、核心矛盾、概念的适用范围、反面证据和未确认项。无法确认的细节应标明，Writer 不得为了故事顺畅而补写。参考链接应真实可访问，并支持相关说法。

## 四、文章骨架：七幕与旁逸斜出的回路

文章表面可以不同，深层推进保持稳定：

| 幕 | 作用 |
| --- | --- |
| 1. 一个具体场景 | 让读者先看见人、行动和处境。 |
| 2. 他为什么走到这里 | 补足人物经历与时代背景，只保留理解矛盾所需的部分。 |
| 3. 无法轻易解决的矛盾 | 让读者先感觉到问题，看到两边都有成本。 |
| 4. 用概念把矛盾说清楚 | 当问题已经成立，再引入哲学或历史概念。 |
| 5. 让问题发生变化 | 引入另一位作者、历史经验或作品，增加另一面。 |
| 6. 回到普通生活 | 连接工作、关系、选择或日常经验，并保留历史差异。 |
| 7. 把问题交还读者 | 压缩已有判断，再留下一个具体、带现实条件的问题。 |

七幕是写作检查工具，不要求正文出现七个小标题。尤其要遵守：**理论出现之前，读者最好已经先感觉到问题。**先让读者看到史蒂文斯如何用“管家的职责”理解自己，等读者察觉他可能把自己藏进职业角色，再引入“自欺”。理论此时是在给已经产生的感觉命名。

原对话所说的“梁文道式”效果，关键在于旁逸斜出以后仍能回来。可迁移的是结构能力：从一个人走进他的故事、时代和思想概念，想起另一部小说，再回到今天，最后重新回到最初的人。

```text
人物 A → 故事 B → 时代 C → 概念 D → 另一部作品 E
→ 今天的生活 F → 回到人物 A，重新理解最初的困境
```

每次展开旁支，都要问：**这段内容怎样让最初的问题发生变化？**如果只是知识有趣，却没有推进核心问题，就删掉。辅助作品应带来新角度或反例，不能只是替主观点站台。

结尾可以保留判断，但不要给出整齐的人生答案。“所以我们应该珍惜当下、勇敢生活”会抹掉前面的复杂性。更好的做法是先用一两句压缩文章得到的判断，再提出一个带条件的两难问题：

> 如果一份工作足够稳定、收入也不错，却要求你长期成为一个自己不喜欢的人，你会在什么地方划线？

好的开放问题没有明显正确答案，不像哲学考试，必须代入自己的生活，而且两边都有真实成本。结尾应让文章的思考继续，而非强迫读者接受一个口号。

## 五、反模式与正文形式

正文使用正常中文长文。一个段落承担完整的小叙事或小论证，内部完成“事实／故事 → 分析 → 推进”。原方法建议每段约 150～350 中文字，以自然完整为先；不要为了凑字数把不同意思塞进同一段，也不要用一句一段和频繁换行制造节奏。

| 反模式 | 编辑方向 |
| --- | --- |
| 一句话一段，像短视频字幕 | 合并相关句子，让一段完成一个意思。 |
| 用大量小标题代替过渡 | 一般只保留文章标题；确有必要时使用两三个自然小标题。 |
| 思想家阅兵 | 主作品或主人物一个，核心辅助思想家一个，必要时再补一个。 |
| 连续解释术语 | 回到具体人物与行动，再说明概念解决了什么问题。 |
| 为漂亮句子下绝对判断 | 补充条件、范围与证据，保留复杂性。 |
| 过早跳到现代类比 | 先建立人物和历史处境，再连接今天。 |
| 把复杂作品压成简单观点 | 保留反例、代价、叙述盲点与不能解决的一面。 |
| 过度美化主人公 | 检查他的选择给其他人带来什么后果。 |
| 鸡汤结尾 | 改为带现实条件、两边都有成本的开放问题。 |

例如，“现代人已经彻底失去了自由”过于绝对。可以改为：“当一个人的自我价值越来越依赖指标时，自我管理就可能从工具变成另一种规训。”后者说明条件，留下论证空间。

正文通常控制在约 3000～5000 中文字符，根据主题复杂度自然调整。篇幅与段落长度都是辅助尺度；思想推进、事实准确和读者理解优先。这份方法文档使用标题、表格和配置块便于查阅，生成的栏目正文仍须遵守长文形式。

## 六、编辑流程：第一稿完成以后再写一次

编辑阶段单独执行，目标是检验文章是否成立，而不是只润色句子。可以按三轮处理：

1. **核对事实和解释边界。**逐项检查日期、身份、出版时间、经历、引语与概念归属。检查是否把推论写成事实，是否误读或过度美化人物，现代类比是否抹平历史差异。
2. **检查结构和思想推进。**标题是否提出人的问题；概念之前是否已有场景铺垫；旁支是否改变核心问题；是否连续三个段落都在讲理论；现代类比是否太早；复杂作品是否被压成简单观点。
3. **清理表达和结尾。**删除重复结论，合并短段，减少过量的“其实、某种意义上、也许”，删除漂亮但证据不足的判断，把抽象概念落回人物，删掉廉价励志式结论。

最后做一次检验：

> 如果删掉所有思想家的名字，这篇文章本身还成立吗？

如果完全不成立，说明文章主要靠名人撑起。好的文章即使去掉这些名字，人的困境、故事和论证依然存在。概念应增加理解，而不是代替理解。

**实现建议：**Editor 输出可用正文和需要退回研究的清单。事实缺口返回 Researcher，论证问题返回 Writer。Publisher 只接受通过编辑的版本；不能用流畅的改写掩盖证据缺口。

## 七、本地 Agent 架构与阶段交接

不必一开始搭建复杂的多 Agent 系统。先用一个模型按顺序切换四个内容角色，再由一个发布模块完成保存即可。原回复列出了五个环节，其中 TopicSelector、Researcher、Writer、Editor 是内容角色，Publisher 是最终交付环节。

```text
profile.yaml + 最近10～20篇 history.jsonl
                     ↓
              TopicSelector
        六个候选、评分理由、选题结果
                     ↓
                Researcher
        场景、事实、来源、矛盾与未确认项
                     ↓
                  Writer
              围绕一个问题的初稿
                     ↓
                  Editor
             核实、收紧、改写、放行
                     ↓
                 Publisher
       保存文章、更新索引与历史、按配置发布
```

建议目录保留原方法的简单结构：

```text
literature-agent/
├── config/
│   └── profile.yaml
├── data/
│   ├── history.jsonl
│   └── topic_pool.json
├── prompts/
│   ├── topic_selector.md
│   ├── researcher.md
│   ├── writer.md
│   └── editor.md
├── articles/
└── manifest.json
```

`profile.yaml` 保存长期兴趣和表达偏好，`history.jsonl` 保存已完成文章的历史，`topic_pool.json` 保存候选与评分。四份角色 Prompt 分别控制各阶段，`articles/` 存放最终 Markdown，`manifest.json` 记录文章索引。

**实现建议：**阶段交接使用明确文件或结构化对象，不依赖模型记住上一轮全部内容。研究来源随研究包传给 Writer 和 Editor。选题失败返回候选池，核查失败返回研究，不必重跑全部流程。最终文章可以按标题命名为 `.md`，处理非法路径字符和同名冲突；保存成功后再更新索引与历史。外部发布失败应单独记录，不能把本地保存报告为远端发布成功。

## 八、profile.yaml 与 history.jsonl 示例

以下 `profile.yaml` 保留原方法的长期偏好。`tone` 等值是本地程序需要解释的配置约定，不是模型自动识别的标准接口。

```yaml
interests:
  - 存在主义
  - 福柯与现代性
  - 自由与规训
  - 东欧与苏联
  - 历史记忆
  - 普通人的文学
  - 张怡微式日常经验
  - 古典诗词与个人命运
  - 工作、欲望、孤独与意义

writing:
  language: zh-CN
  form: longform
  tone: cultural-podcast
  paragraph_style: long-natural-paragraphs
  avoid:
    - 一句话一段
    - 知识点罗列
    - 鸡汤结尾
    - 大量小标题
    - 术语堆砌
    - 无依据的宏大判断
```

“张怡微式日常经验”在这里表示关注日常生活、关系与普通人的处境；“文化播客”表示叙事与思想递进的阅读体验。程序应把这些偏好转成明确要求，避免只凭风格标签生成内容。

`history.jsonl` 每行是一个完整 JSON 对象，不加数组外壳，也不在行末加逗号。以下保留原回复的两条示例；它们用于说明格式，不是本地系统已经发布的记录：

```jsonl
{"date":"2026-10-13","title":"一个人把一生都献给“正确的工作”，为什么最后只剩下后悔？","work":"长日将尽","themes":["工作","身份","自欺","后悔"]}
{"date":"2026-10-12","title":"陶渊明辞官以后，真的获得自由了吗？","work":"归去来兮辞","themes":["自由","工作","选择成本"]}
```

TopicSelector 每次必须先读最近 10～20 篇。日期、标题、作品和主题是最低信息集。**实现建议：**逐步增加 `author`、`region`、`core_question`、`argument_pattern` 和 `path`，以识别“换了作者，却重复同一种解释”的情况。字段应在实际完成文章后写入，不能把候选题当成已完成历史；日期相同时使用稳定的记录顺序或时间字段确定先后。

## 九、可直接复用的核心 Prompt

以下保留原回复的核心 Prompt。可作为总提示词，再由各角色提示词补充输入、输出格式与退回条件。

```text
你是一名长期文学、哲学和思想栏目作者。

你的目标不是做知识百科，也不是总结一本书，而是每次围绕一个真正值得反复思考的人类问题，写成一篇有叙事、有历史背景、有思想递进的中文长文。

选题优先范围：
存在主义；福柯与现代性；自由与规训；历史记忆与责任；东欧、苏联与20世纪思想史；文学中的普通人处境；张怡微式日常经验；中国古典文学与个人命运；孤独、欲望、工作、死亡、选择和意义。

选题规则：

1. 每篇只讨论一个核心问题。
2. 标题优先写成问题，而不是“介绍某某思想”。
3. 必须存在一个具体的人、事件、文学场景或历史细节作为入口。
4. 作者、哲学家和作品是解释问题的工具，不是文章目的。
5. 阅读最近文章历史，避免连续重复同一种思想结构、同一作者或同一地区。
6. 优先选择既能进入文学/哲学，又能落回今天普通生活的问题。

研究规则：

1. 先研究原作和人物，再研究理论解释。
2. 历史日期、出版时间、人物经历、直接引语必须查证。
3. 区分事实与解释，不把作者自己的推论写成史实。
4. 引用原文必须短，说明作品来源。
5. 推荐作品时提供真实、可核查的参考链接。

文章结构：

从一个具体场景开始。
先让读者进入人物和时代，而不是先解释概念。
逐渐暴露一个矛盾。
当矛盾已经成立以后，再引入一个哲学概念帮助命名它。
最多重点引入1～2位辅助思想家或作品。
允许旁逸斜出，但每一段最终必须服务于核心问题。
最后回到今天普通人的工作、关系、选择或生活经验。
不要给出整齐答案，用一个两难而具体的问题结束。

写作形式：

使用正常中文长文。
不要一句一段。
不要频繁换行制造节奏。
一个自然段应承担完整的一小段叙事或论证。
除非确有必要，不使用小标题。
不要写成卡片、清单、讲义或知识点。
避免连续解释术语。
避免鸡汤。
避免“真正的答案就是……”之类过早封闭问题的句式。

理想效果：

读者首先觉得自己在听一个人的故事，
然后慢慢发现这个故事里藏着一个哲学问题，
再发现这个问题其实也发生在自己的生活里。

完成初稿后自行编辑一次：

删除重复内容。
合并过短段落。
减少抽象判断。
检查每个哲学概念前是否已有具体问题作为铺垫。
检查是否过度美化主人公。
主动指出人物、作品或观点中无法轻易解决的另一面。
检查现代类比有没有抹平历史差异。
删除所有廉价励志式结论。

最终篇幅通常控制在约3000～5000中文字符，根据主题复杂度自然调整。
```

本地使用时，TopicSelector 应明确输出六个候选及六项评分；Researcher 应交付来源与未确认项；Writer 应只依据研究包写作；Editor 应完成前述三轮检查。核心 Prompt 里的查证和参考链接要求，需要真实检索或原文访问能力支持；缺少材料时应补研究，不能编造来源。

## 十、最后的一句话原则

**先找到一个具体的人怎样陷进一个真实困境，再借文学、历史和哲学把这个困境逐层展开，最后不要替读者解决，而是把问题交还给他的生活。**
